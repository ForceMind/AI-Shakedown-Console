# 故障排查

先找到页面或终端中最接近的现象，再按顺序操作。不要为了解决单个问题关闭系统安全功能或结束无法确认归属的进程。

## 中文输入与候选词

先根据现象选择对应处理方法。这两类故障发生在不同层，不能用同一种方式处理。

### 候选词出现，但确认时被打断或发送

这是网页组合事件问题。`v23` 起页面独立跟踪 `compositionstart` / `compositionend`，并兼容 `keyCode 229`：

1. 确认页面左上角显示 `v25` 或更高版本。
2. 已安装 PWA 时，留意“发现内容更新”提示并点击“立即刷新”。
3. 仍显示旧资源时访问 `/?refresh=25-r2`，再强制刷新。
4. 在消息框完成候选词选择；普通 `Enter` 应换行，不会发送。
5. 只有 `⌘ + Enter`（macOS）或 `Ctrl + Enter`（Windows/Linux）才发送。

如果普通浏览器窗口中也会复现，暂时关闭会改写输入框的扩展后再试。

### Edge PWA 输入拼音但没有候选窗

如果按键和拼音已经进入输入框，但系统候选窗完全不出现，这通常不是网页、Service Worker 或缓存中的 JavaScript 故障。

macOS 上由 Edge/Chrome 安装的 PWA 会通过单独生成的原生 App Shim 运行。候选窗由 macOS 输入法和当前原生文本输入上下文绘制，网页只能接收组合事件，不能命令系统显示候选窗。第三方输入法、浏览器更新或 PWA 进程生命周期可能使 App Shim 的输入上下文失效；此时普通 Edge 标签页可以正常输入，只有已安装的 PWA 没有候选窗。

### 一劳永逸的方案

已确认重装 Edge PWA 后候选窗可以恢复，但 Edge 更新并重启后会再次失效。这说明重装只刷新了 App Shim 的原生文本输入上下文，并没有消除 Edge 更新对它的影响。

需要长期稳定使用 WeType 等第三方输入法时：

1. 在 Edge PWA 设置中找到“macOS 中文输入法稳定方案”，点击“复制地址”。
2. 打开 Safari，粘贴地址并访问。
3. 选择 Safari 的“文件 → 添加到程序坞”。
4. 以后从新生成的 AI Shakedown Console 图标启动。

Safari Web App 仍是独立窗口、支持当前项目的 manifest 与 Service Worker，但它不依赖 Edge App Shim，因此 Edge 更新不会再次破坏它的文本输入上下文。由于 Safari 与 Edge 使用不同的站点存储，首次打开时需要重新填写连接配置；不要通过公开聊天或截图传递 API Key。

### 临时恢复 Edge PWA

如果暂时不能迁移，按以下顺序恢复：

1. 完全退出 AI Shakedown Console PWA，并完全退出 Edge，再重新打开验证。
2. 在 macOS 输入法菜单临时切换到系统自带“简体拼音”。如果系统拼音正常而第三方输入法异常，优先更新或重启第三方输入法。
3. 打开 `edge://apps`，卸载 AI Shakedown Console。**不要选择清除浏览数据/站点数据的选项**。
4. 完全退出并重新启动 Edge，再从线上站点安装 PWA。
5. 如果仍未恢复，更新 Edge 和输入法；临时使用普通浏览器标签页。

不清除浏览数据时，当前站点的配置和对话通常会保留；清除站点数据会删除浏览器内保存的内容。不要手工删除 Edge 用户目录或 `Web Applications` 目录作为第一步。

#### 为什么重新安装会恢复

重新安装不只是刷新网页缓存。它会重新生成 PWA 的原生 App Shim、应用身份和特设签名（ad hoc code signing），重新登记到 macOS，并建立新的浏览器进程与文本输入上下文。已确认的案例中，重新安装后候选窗恢复，而网页资源和 Service Worker 前后完全一致；重建后的 App Shim 仍与 Edge 主程序存在补丁版本差异，因此版本数字不同也不是这次故障的原因。Edge 下一次更新重启后问题再次出现，进一步证明这属于 App Shim 生命周期问题。

维护者判断原则：只有问题也能在普通浏览器标签页复现，或页面已经收到 `compositionstart` / `compositionend` 却处理错误时，才应修改前端输入逻辑并发布新版本。

技术背景可参考 [Chromium App Shim 说明](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/app_shim/README.md)、[Chromium macOS Web App 集成目录](https://chromium.googlesource.com/chromium/src/+/HEAD/chrome/browser/web_applications/os_integration/mac/) 和 [Microsoft Edge 的 macOS PWA 特设签名策略](https://learn.microsoft.com/zh-cn/deployedge/microsoft-edge-policies/adhoccodesigningforpwasenabled)。

## 本机桥接与启动器

### macOS 提示没有正确的访问权限

不要双击 `.command`，打开终端执行：

```bash
bash "$HOME/Downloads/ai-shakedown-codex-macos.command"
```

如果文件名含 `(1)` 或空格，在终端输入 `bash `，把文件拖入终端，再按回车。

### macOS 阻止访问下载文件夹

打开“系统设置 → 隐私与安全性 → 文件与文件夹 → 终端”，允许访问“下载”。不需要开启完整磁盘访问。

### 启动失败：没有找到 Node.js

启动器要求 Node.js 18+，并会依次检查：

- 当前 `PATH` 中的 `node`；
- Codex 桌面版常见的内置运行时目录；
- 常见系统安装位置。

处理方式：

1. 如果已安装 Codex 桌面版，先更新到当前版本后重新运行脚本。
2. 在终端运行 `node --version`；如果命令不存在，安装 Node.js 18 或更高版本。
3. 安装后关闭并重新打开终端，再运行下载脚本。

### 找不到 CLI 或尚未登录

在同一个终端运行对应命令：`codex`、`agy`、`gemini`、`claude` 或 `opencode`。

- 命令不存在：先按对应工具官方文档安装。
- 命令存在但要求登录：完成登录后退出，再重新运行下载脚本。
- GUI 能用但终端找不到：确认 CLI 安装目录已经加入 `PATH`。

### 端口被占用

正常情况下无需处理。启动器会自动寻找最多 100 个后续空闲端口，不会结束无关程序。

如果仍失败：

1. 在网页点击“停止后台连接”；
2. 关闭不需要的本地开发服务；
3. 重新下载并运行脚本；
4. 检查状态目录中的日志。

### 连接成功后还要一直开着终端吗

不需要。脚本显示后台启动成功后即可关闭终端。需要停止时使用网页中的“停止后台连接”。

### 下载新版后仍连接旧代码

1. 在网页点击“停止后台连接”。
2. 删除下载目录中重复的旧启动脚本，重新下载固定文件名。
3. 运行新脚本，它会重新下载当前版本桥接。
4. 保持原页面或 PWA 打开；它会自动发现桥接和实际端口，无需等待新窗口。

### 运行脚本后弹出重复网页窗口

`v25` 起，页面会在限定的 100 个候选端口内自动发现带正确令牌的桥接。桥接会等待现有页面连接，不再重复开窗；只有原页面已经关闭时，才会尝试唤起已安装应用，找不到应用时才打开默认浏览器。

如果新脚本仍重复开窗，说明运行的可能是旧下载文件：停止后台连接，删除重复脚本，再从显示 `v25` 或更高版本的页面重新下载。

### `unknown variant readOnly`

这是旧桥接使用了无效沙盒值。有效值为 `read-only`、`workspace-write` 和 `danger-full-access`。当前版本固定使用 `read-only`。

停止旧桥接并重新下载、运行当前启动脚本即可。

### 页面无法访问 `127.0.0.1`

部分浏览器会询问本地网络访问权限，请允许当前站点访问本机服务。还应确认：

- 当前页面与下载启动器时的站点 Origin 相同；
- 地址仍包含脚本加入的配对参数；
- 防火墙或安全软件没有阻止 Node 监听回环地址；
- 桥接日志中没有立即退出的错误。

## API 连接

### “检查连接”失败但聊天可能可用

“检查连接”会先请求模型列表（路径不为空时），再发送一张 16×16 像素测试图片。Azure OpenAI 或自建网关没有标准 `/models` 接口时，可把模型列表路径留空；页面仍会执行图片能力检查。

认证、配额、网络或网关错误会让整个检查失败；只有上游以 400/415/422 明确表示不接受图片时，页面才会显示“连接正常 · 不支持附件”并保留纯文本聊天。

### 没有附件按钮

附件按钮只对最近一次真实图片检查成功的配置显示。依次确认：

1. 当前状态是否为“连接正常 · 支持附件”；
2. 修改过协议、Base URL、请求路径或模型后是否重新点击了“检查连接”；
3. 模型本身是否支持视觉输入，而不是仅模型系列名称相似；
4. 本机 Codex、Antigravity、Gemini CLI、Claude Code 和 OpenCode 桥接当前不接收附件，因此不会显示按钮。

### 选了文件但没有加入消息

- 每条消息最多 6 个附件，合计不超过 12 MiB；图片 5 MiB、文本 1 MiB、PDF 10 MiB。
- 不支持的二进制文件会被拒绝。
- 扫描版 PDF 没有文字层，当前不做 OCR；请先转换为可选择文字的 PDF 或纯文本。
- 浏览器禁用 IndexedDB、站点存储空间不足或隐私策略阻止存储时，附件无法持久保存。

### 附件刷新后丢失或提示数据已丢失

附件内容位于当前 Origin 的 IndexedDB。切换域名/端口、清除站点数据、无痕会话结束或浏览器自动回收站点存储，都会让旧消息的附件引用失效。重新选择文件即可；不要依赖浏览器站点存储作为原文件备份。

### CORS 错误

可选方案：

1. 让上游允许当前页面 Origin；
2. 在 Cloudflare Pages 部署中开启同域代理，并把上游 Origin 加入 `ALLOWED_UPSTREAMS`；
3. 使用你控制的 OpenAI-compatible 网关。

不要通过禁用浏览器安全策略或发布无白名单开放代理来绕过 CORS。

### HTTPS 页面无法连接 HTTP 地址

浏览器会阻止 HTTPS 页面的混合内容。Ollama、LM Studio 等本机 HTTP 服务适合在本地 HTTP 页面测试，或通过安全的本机桥接/受控 HTTPS 网关接入。

### Worker 返回“尚未配置 ALLOWED_UPSTREAMS”

在 Cloudflare Pages 项目的“设置 → 变量和密钥”添加普通文本变量 `ALLOWED_UPSTREAMS`，值为允许的 Origin，多个值用英文逗号分隔。保存后创建新的部署。

### Worker 拒绝上游

白名单比较完整 Origin，包括协议、主机和非默认端口。例如：

```text
https://api.example.com,https://gateway.example.com:8443
```

不要填写路径。确认 Base URL 的 Origin 与白名单完全一致。

### API Key 正确但仍 401/403

检查：

- 认证方式是 Bearer、`x-api-key`、查询参数还是自定义头；
- Base URL 和路径是否重复包含 `/v1`；
- Key 是否有模型或项目权限；
- 自定义请求头 JSON 是否覆盖了认证头；
- 同域代理请求检查器中显示的上游是否正确。

## PWA 与缓存

### 部署后仍显示旧版本

1. 确认部署包内 `index.html`、`script.js` 和 Service Worker 都是同一版本。
2. 打开 `/?refresh=25-r2` 绕过旧入口缓存。
3. 已安装 PWA 时等待更新提示并点击“立即刷新”。
4. 仍无更新时，在浏览器站点设置中清除该站点缓存后重新打开。

清除站点数据也会删除浏览器内保存的配置和对话；操作前自行确认是否需要保留。

### 没有“安装为桌面应用”按钮

- 必须通过 HTTPS 或 localhost 访问。
- 浏览器需要支持 `beforeinstallprompt`；Safari 使用系统菜单，不一定显示页面按钮。
- 已安装、无安装资格或浏览器策略禁用时，页面不会显示按钮。

### 离线打开后无法调用模型

这是预期行为。离线缓存只保证应用外壳和已缓存静态内容可用；远程 API 仍需网络，本机 AI 仍需桥接运行。

## 对话、配置与导入

### 刷新后数据不见了

确认没有使用无痕窗口、浏览器没有禁止站点存储、站点 Origin 没有变化，并且没有点击“清除全部本地数据”。`http://localhost:4173` 与线上 HTTPS 地址属于不同存储空间。

### 导入文件被跳过

可能原因：

- 文件超过 20 MiB；
- 总文件超过 60 MiB 或 200 个；
- 文件不是支持的 JSON/JSONL 结构；
- 文件名看起来像凭据、密钥或敏感配置；
- 记录中没有可识别的用户/助手消息。

### Token 或费用一直为 0

只有上游返回 usage 时才累计 Token。费用还需要在设置中手动填写当前模型的输入/输出单价。

## 仍未解决

复制设置中的请求检查信息并先删除业务敏感内容，再提交 GitHub Issue。不要公开 API Key、Bearer Token、本机路径中的个人信息或完整机密对话。
